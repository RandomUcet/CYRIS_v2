# CYRIS 2.1.0-rc.3 — Notification usability and accessibility candidate

**Status:** INTERNAL RELEASE CANDIDATE, NOT DEPLOYED. The last published stable release remains `v2.0.3`. This candidate is branched from the CI-verified `2.1.0-rc.2` source, with no production migration or tag.

## Changes relative to rc.2

- Rebuilt the notification dropdown with theme-aligned foreground and background contrast, a responsive mobile layout, readable rows, keyboard Escape and click-outside dismissal, labelled icon controls and focus indicators.
- Corrected the literal `notification.markAllRead` key on the user's screenshot to the existing localized `action.markAllRead` in **CS, EN, DE and PL**.
- Protected the notification list against late polling results from a different exercise; errors are visible, with refresh/retry controls and explicit mutation failures instead of silently discarding them.
- Notification actions are disabled in read-only administrator **View As** mode; user-facing navigation accepts only local paths.
- Added automatic source-level translation-key regression coverage specifically for the notification center and all four selectable languages.
- Continues previous `rc.2` work: visual structure, command/DEFCON, medical forms, service status, event scoped registry/relationships, scenario media, JSOC synthetic logs, security and role hardening.

## Acceptance required before stable v2.1.0

- CI on the exact proposed tag commit: `pnpm build`, `pnpm typecheck`, test suite and version integrity; a green CI run is not a substitute for browser inspection.
- Exercise role walk-through: admin, EXCON, crisis team, JSOC, laboratory requester/lead/worker, medical, evaluator, regular student and View As.
- Browser verification at desktop/tablet/mobile widths; notifications in CS, EN, DE and PL (including mark all read, dismiss, no data, error response and cross-event switch), contrast and keyboard operations.
- Test migrations on a disposable PostgreSQL database and verify backup/restore before updating an existing Preview environment.
- Confirm real CYRIS infrastructure monitoring remains separate from simulation and not visible to crisis team without the explicit permission.
- Ensure that no new tag is created while deployment procedures, role-scope security, or migrations remain unverified.
