# CYRIS v2.4.12 — Participant notification inbox

## Improvements
- EXCON broadcasts now display the **actual message body** instead of repeating the title. Notice type is visibly labeled: Announcement, Situation update, Instruction or Urgent alert.
- Search loaded notifications by title, body or type, and filter by **All**, **Unread** or **Important** (ACTION and URGENT severity).
- No-result state differentiates empty inboxes from filtered-out messages.
- Background tabs pause notification polling; returning to the tab triggers a fresh fetch. Existing foreground refresh, read/dismiss controls, View As read-only mode and exercise scoping remain unchanged.
- Controls are localized in Czech, English, German and Polish.
- Focused regression tests cover notification body extraction and unread, priority and text search.

## EXCON broadcast composer safety
- Saved draft editing no longer permits an accidental **Send now** action that would leave a separate unsent draft behind; operators can save the draft or make a new copy.
- Existing draft, sent, failed or cancelled broadcast plans can be copied into a new composer session. The copied message is never sent automatically, and its prior plan UUID/revision/idempotency identity is **not** reused.
- Instant delivery and plan updates now share consistent readiness rules. No concurrent plan mutation and direct send, with client-side checks mirroring title (3–120), message (3–900) and team selection validation.
- Recipient count and server-side authorization remain authoritative at delivery time, including cross-exercise scope and active team status.
- Filtered notification inbox no longer offers misleading event-wide **Mark all read** while only a subset is visible.

## Boundaries and verification
- Search/filter work only on the **last 100** authorized notifications returned for the selected exercise; the panel is not a complete historical archive.
- Filters never send mutations or change recipients, audit logs or underlying exercise data.
- No new schema migrations, backend permissions, new SMTP/SMS channels or autonomous AI delivery.
- Exact-head GitHub CI (build, types, regression and isolated backup recovery) is required before release. CI is not a substitute for browser acceptance testing.

## Update on Ubuntu after official Release is published
```bash
sudo cyrisctl self-update
sudo cyrisctl github verify
sudo cyrisctl update --version v2.4.12
sudo cyrisctl status
sudo cyrisctl doctor --full
```
