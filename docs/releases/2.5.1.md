# CYRIS 2.5.1 — operational hardening (development)

Branch begins from released-scope 2.5.0 main commit 5fb7068. Release workflow for 2.5.0 is running independently. Focus: exercise time consistency, licence registry usability, access boundaries, regression fixes and operator feedback. Do not publish until validated.

Licence status now derives from the exercise clock and event timezone, with date-only inclusive validity and a separate administrative status. Invalid timezone is unknown rather than host-clock fallback. Manual what-if remains. Registry list identity scope includes user, preview and capabilities. Contract tests cover timezone midnight boundaries. CI pending.

Audit now resolves current account names for actors and user targets in paginated queries, including literal name search before pagination. UUIDs remain in a technical inspector, not primary columns. Timestamp no longer repeats the date. No immutable event or archived payload is modified; names are current, not historic snapshots.

Intelligence Center split into four task-oriented work areas, preserving mounted form and job polling state. The navigation includes local module filtering (authorized routes only) and full label tooltips, while preserving branding. Technical AI IDs move out of everyday views. Browser acceptance pending.

Licence holder/issuer selection now uses the permission-filtered registry picker with server-side entity type filtering before the result limit. No bulk person/organisation dropdown, no UUID copying. Creation checks distinct selected records and fences asynchronous form responses against identity/tab changes.

First diagnostics increment: `sudo cyrisctl diagnostics --summary --minutes 60` produces JSON containing bounded per-service fixed-category log counts only. No raw logs, excerpts, host details, credentials, identifiers or model calls. Unavailable service sampling is explicit. Counts are matching log lines, not distinct incidents. This is a safe transport input for subsequent local Spark diagnosis; not yet Spark inference or an automated monitor.

Spark diagnostics stage 2: platform-managed endpoint and System Health panel accept only a strict fixed-category CLI summary, use the managed Spark gateway and regular shared admission with an exclusive diagnostic scope, validate every finding against positive observed counts, and allow copying a structured report. No raw logs or autonomous changes. CLI-to-API direct authenticated transport and scheduled notifications remain follow-up. Contract tests cover injection-shaped inputs and unsupported findings.

Forensic request evidence/device references and evidence relationship targets now use the shared event-scoped search picker instead of raw UUID input. Workspace instances are scoped to exercise and session identity; forensic create action uses event-specific permission. Custody recipient selection remains a separate backend-authorized directory task. Global picker results are additionally constrained to requested event and type. CI and live browser verification pending.

Evidence custody transfer repair: old frontend payload did not match the API. Replaced raw user/unit UUID inputs with a bounded resource-authorized recipient search and explicit storage choice. Transfers require a reason, valid same-exercise active recipient, and atomic row-locked custody/audit update. History displays actual occurredAt, holder names (current directory, not historical snapshots), and real storage labels. Preview users excluded from recipient directory. CI pending.

CLI Spark analysis: `sudo cyrisctl diagnostics --analyze --minutes 60 --locale cs` gathers fixed categories and calls the admin diagnostics endpoint through the Compose loopback API only (configured port, no proxy/redirect). Interactive local administrator login, in-memory session, logout in finally; no password or token arguments, no Spark credential export. On analysis failure the deterministic source summary is still printed and the command fails. Mocked transport tests cover success and logout on failure. LDAP/OIDC and unattended collection require separate scoped authentication design; scheduled monitoring is not yet enabled.

Storage management first increment: `sudo cyrisctl storage` or `sudo cyrisctl storage --json` measures host filesystems, fixed CYRIS service directories, backups, Docker/containerd directories and Docker logical accounting. Time-bounded read-only commands, local socket on the host only; no raw paths or inspect payloads in the structured report. System Health imports a validated manual snapshot, displays available capacity and an 85% unavailable-capacity warning. No cleanup, remote shell or automatic host collection enabled. Tests cover size parsing and unavailable measurements.

Admin maintenance console: exact predefined API liveness, dependency readiness and existing bounded Spark inference probe. Dedicated platform-managed check endpoint rejects extra fields and preview mode; actions are audited, dependency responses omit error strings. No child process, shell, Docker access or system mutation. Tests cover action validation and preview rejection. Host-only maintenance remains cyrisctl/SSH.
