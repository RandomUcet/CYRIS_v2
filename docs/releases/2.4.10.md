# CYRIS v2.4.10 — EXCON Control Center: drafts, scheduled communications and safe automation

## New organizer workflows
- **Save editable announcement drafts**, revise them with revision-aware optimistic concurrency, and schedule automatic delivery with a real-world local time picker.
- **Quick message templates** for phase opening, requests for SITREP and general coordination; organizers can edit every word before sending.
- **Cancel** pending or draft notices safely, while preserving the historical plan/audit record. Already sent notices cannot be recalled or silently changed.
- Statuses: DRAFT, SCHEDULED, SENT, CANCELLED, FAILED. Operator sees schedule, delivery count and failure reason. Stored plans are accessible only to users with event-level `scenario.manage` rights.
- Existing immediate send, four severity/types, team/whole-event targeting, audience preview, read receipts, and human-approved AI writing assistance continue to work.

## Server-side schedule (not a browser timer)
- New migration **0030** introduces `exercise_broadcast_plans` (per-event, creator, target, text, status, revision and timestamps) with validity constraints and a due index.
- Existing Worker checks due real-world UTC times during the 4-second scenario reconciliation cycle. It locks each plan row `FOR UPDATE SKIP LOCKED` so multiple worker replicas do not deliver twice.
- Delivery is atomic with status transition, distinct per-recipient in-app notifications, immutable audit event and archival outbox entry; no email fanout and no autonomous AI sending.
- The worker sends only for **ACTIVE** exercises and respects event-wide operational holds for scenario/briefing modules. DRAFT/PREPARATION or holds defer without losing the plan. CLOSED/ARCHIVED marks a pending plan FAILED without delivery.
- Cross-event and archived unit targets are rejected. Active memberships, enabled accounts, and notification opt-outs are checked **at delivery time**. Urgent notices are mandatory. Empty recipients, archived target or >5,000 recipients fail visibly rather than silently.
- Schedules cannot be backdated or more than 90 days in the future. Saved drafts cannot silently mutate once scheduled or sent.

## Tests and deployment gate
- Isolated PostgreSQL tests for organizer-only permissions, draft revisions, schedules, cancellations, multi-worker duplicate prevention, hold and lifecycle gates, correct team targeting, opt-out vs urgent delivery, audit archival and per-event isolation.
- Existing full CI, backup restore smoke, and release gate required. Migration must run before new worker and API version.
- Manual acceptance: organizer + two participant roles in browser; timezone/DST, paused exercise and restart recovery; no automatic changes to an existing live exercise.
