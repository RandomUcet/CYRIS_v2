## Changes compared to v2.0.3

- Consolidated navigation, page layout, responsive medical dialogs and DEFCON sound-on-change behavior
- Event-scoped relationship exploration and relationship creation by searching permitted records
- Scenario-data published-batch media manager for six record types; image size and type validation
- Admin-only system diagnostics; auditing displays real timestamps and does not invent source IPs
- Server-authorized, time-limited read-only View As already present in the base release
- JSOC synthetic-only telemetry and EXCON-controlled log creation; restricted event roles and a new database migration `0024_jsoc_synthetic_logs.sql`
- RC.2 hardening: corrected registry image edit capability, no mutation buttons in View As, accurate role scopes and bilingual role browser
- Canonical registry-backed relationship picker: permission-filtered database lookup works even if Typesense has no matching index projections; self-referential links are rejected by the server

## Deployment safety

This RC does not alter `main` or production. Do not run seeds against the operator's live or local preview data. Existing local preview has isolated Docker volumes and custom configuration; preserve those settings. Apply migrations only after a verified backup and disposable-database rehearsal. CI is necessary but not equivalent to a full browser/role acceptance.

## Known limitations and future backlog

- Images are attached **after** scenario records are published, not during unpublished Spark draft generation.
- Full localized wording and all page-specific responsive visuals require comprehensive browser acceptance.
- Actual JSOC/EXCON/medical student workflow demonstrations require seeded isolated test fixtures and a browser.
- A signed GitHub Release / SemVer tag should be created only after all acceptance checks pass.
