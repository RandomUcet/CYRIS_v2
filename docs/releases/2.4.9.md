# CYRIS v2.4.9 – Exercise broadcast control and fast Spark scenario drafts

## EXCON / organizer broadcasts
- New **Exercise broadcast center** reachable from Admin → Exercises and Command → Exercise broadcasts.
- Four kinds: **Announcement, Situation update, Action instruction, Urgent notice**. Broadcast to all active exercise participants or one **active unit**. No cross-event or archived-team recipients.
- Server-side **recipient preview**; excludes inactive memberships and disabled users, deduplicates multi-team members, honors in-app opt-outs for nonurgent types. **Urgent** broadcasts intentionally override in-app opt-outs; require explicit confirmation in the UI.
- Idempotent UUID nonce prevents retries sending duplicates. Different content under the same nonce is rejected. Delivery and immutable audit are committed in **one transaction**. Maximum of 5,000 recipients, inserted in bounded batches, no external email fanout.
- Recipients see the actual title, body and severity in the existing **Notification Center**, read/dismiss as normal. Organizer history shows delivery totals and **read receipt counts** without individual participant details.
- Never auto-send private scenario spoilers, medical notes or confidential evidence via this broadcast feature; organizers control content. No AI automatically issues or approves broadcasts.

## Spark performance
- **FAST mode (default in the web UI)**: one brief, capped AI request with a strict 45-second provider timeout and 450-token cap generates a small **fictional scenario blueprint** (roles, sites, activities, equipment). CYRIS deterministically creates the full synthetic registry dataset and connected relationships locally, in one request/atomic draft update.
- The same **108-record SMALL preset** no longer requires about 12 serial AI calls. The detailed **DETAILED** mode is preserved as an explicit option, continuing to generate individual pages of up to 12 AI-authored records.
- AI words supply contextual descriptions; the structured names, locations, asset identifiers and relationship links in FAST mode come from the deterministic local generator. This speed/variety tradeoff is clearly labeled in the UI.
- Both modes preserve editable draft preview, quality preflight, image attachments, resume after failure, safe publication and audited generated-data cleanup.
- The 45-second limit applies to each fast-mode **provider request**, not the full user workflow. Actual throughput still depends on the connected DGX Spark model, queue, network and server; no production benchmark claimed.

## Quality & security
- Validation for 6 scenario record kinds and all cross-kind links, deterministic draft generation, explicit organizer-only exercise messaging, active event and unit checks, client idempotency and same-event transaction/advisory lock.
- Tests include real isolated PostgreSQL: audience opt-out/urgent controls, authorizer denial, idempotent retransmit and nonce misuse, cross-event unit isolation, audit transaction rollback and read receipts; scenario data fast-mode one-call generation and publication; frontend wiring.
- No schema migrations, destructive event purge, change to active identities, or automatic server deployment.
- **Acceptance required:** manual browser use with organizer + two unit-scoped participants; real DGX Spark load and response validation, plus A4 print checks from previous releases.
