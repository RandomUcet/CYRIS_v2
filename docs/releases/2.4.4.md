# CYRIS v2.4.4 — Medical patient / Relations consistency

## Correctness fix
- Updating the linked person in a medical encounter now synchronizes the active `PATIENT_RECORD` edge in Relations. Prior patient links are soft-removed with historical timestamps and audited rather than hard-deleted.
- Reassigning a patient adds the new cross-domain relation, reindexes both endpoint records and updates the patient's medical encounter in **one PostgreSQL transaction**.
- Explicit `personId: null` clears active patient links; an explicit unchanged person reconciles a missing legacy edge but does not create duplicates.
- Unrelated manually created relationship types remain untouched.
- Per-encounter database row locking serializes competing updates; audit and search-outbox writes are committed alongside medical and relationship updates.
- Exercise and entity type isolation remains enforced by the v2.4.3 medical reference checker and a second validation in the relationship service.

## Evidence
- Disposable PostgreSQL regression covers unchanged reassignment, old-edge soft removal, new-edge creation, unrelated-edge preservation, null clearing, foreign event denial, legacy relationship repair and transaction rollback upon simulated link creation failure.
- No new schema migrations, destructive deletion, or external service requirements.

## Release gate
- Match all source and deployment version manifests, execute the full exact-head CI including migrations, typechecks, regression and encrypted backup restore, then publish digest-pinned container images and a matching Ubuntu installer.
- This validates code-level behavior, **not** multi-role browser testing of a real CzechCybertron event or operational acceptance.
