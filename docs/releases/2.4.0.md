# CYRIS v2.4.0 — After-Action Insights and Safe Retention Preview

## Changes
- Platform administrator after-action dashboard now includes **UTC daily operational
  and audit activity trends**, distinct audited operators, outcomes and denied/
  failed actions. The dashboard prints on A4 and exports a **numeric-only CSV**
  (in addition to the existing JSON report).
- A non-destructive resource-category selector lets administrators preview the
  *directly counted* resources of a retired exercise by category.
- The preview's server validates the types against the selected event and flags
  that the result covers **database resource rows only**; it never promises
  cross-store or child-table deletion completeness.
- Back-end event-scoped aggregation keeps counts of a different exercise out
  of the selected event report.
- Tests for UTC midnight rollover, permission boundaries, event isolation,
  resource-type validation, and export/print UI guards.

## No destructive purge yet
**Full and partial event deletion remain disabled.** They require a verified
off-host encrypted backup, immutable audit-preservation policy, inventory of
object-store and search-index artifacts, queue freeze, rehearsal on staging and
two-stage explicit confirmation. See
https://github.com/RandomUcet/CYRIS_v2/issues/21

## Scope and limitations
- Reporting contains aggregate counts and does not export private medical text
  or evidence descriptions.
- The activity chart aggregates audit and domain timeline events separately:
  one action may produce multiple entries across the streams; do not interpret
  the combined number as unique incidents.
- Dates in the chart are explicitly **UTC**; the event's local calendar may
  differ around midnight.
- No claim of full browser acceptance, penetration certification, or secure
  host-side administrator backup interface. Host backups remain operator-owned.
- No database migration in 2.4.0; deployment manifest should have
  `migrationsRequired` set to false only if all required prior migrations are
  already installed. Release workflow currently sets true to be conservative.
- Actual production deployment requires a separate operator action.

## Release acceptance
Only publish after exact-head passing CI, successful isolated backup-recovery
smoke and release workflow, plus verified digest-pinned API, worker and web
images. Browser print and role-based behavior should additionally be checked
on a non-production exercise before using an important live event.

## Update Ubuntu after official release
```bash
sudo cyrisctl self-update
sudo cyrisctl github verify
sudo cyrisctl update --version v2.4.0
sudo cyrisctl status
sudo cyrisctl doctor --full
```
