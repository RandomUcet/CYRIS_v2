# CYRIS 2.5.2 — cross-team workflows (development)

Initial increment: forensic lifecycle and transactional request status receipts, approved-only print, exact permission checks, locked status/child writes, and a real draft report save endpoint. Physical lab and digital forensics remain separate capabilities. Automatic team routing, evidence-tab links, reassignments, tests across roles and browser acceptance remain. 2.5.1 release builds independently.

Digital forensics routing: select a configured active unit with digital_forensics capability (one auto-selected, ambiguous explicit team only), assign a least-loaded active eligible examiner with read/accept/work/complete rights, exclude expired/preview accounts, serialize decisions per event/unit and record assignment. An unassigned request remains in the responsible unit queue. Initial request, assignment notifications, audit and activity are transactional. PostgreSQL lifecycle test added. CI pending.

Evidence integration: linked forensic requests and approved conclusions/print links appear on the source evidence, with explicit request entry and preselected authorized source. My requests/assigned work filters are evaluated in PostgreSQL before the existing bounded list page. Current page limit is 100 and complete authorized pagination remains follow-up. Current examiner and unit names replace placeholders in detail. Assignment and status notification text is distinct from lab in every locale. Acquisition storage references and internal notes restricted to staff; linked source IDs filtered. CI pending.

Operations Inbox increment: extends existing My Work rather than adding a redundant module. Includes digital forensic assignments and a personal outgoing requests/results view for tasks, laboratory and forensics, including terminal records and approved-report indicator. Domain-specific unit/event scopes are checked independently; each row retains canonical resource authorization and module outage filtering. SQL filters by requested/assigned/team before loading. Identity-scoped UI, refresh on focus and 20s. Existing forensic integration now consumes its own assignment notification, preventing contamination of later notification fixtures; verifies assigned work and approved outgoing result. Full cross-domain legal/medical integration and large-event pagination performance remain pending.

Navigation availability now also recognizes request-only users for laboratory and forensic queues. Existing personal-view regression expectations updated to include outgoing requests. Work queue switches expose selected state to assistive technology.

Approval queue: My Work includes an awaiting-approval view for completed laboratory and digital forensic reports, with independent domain read/approval capabilities and exact resource checks. Approved records leave the queue. Fixed missing event-route assertion for forensic finding creation; regression coverage added. Exact-head CI and browser acceptance pending. General document approvals and legal/medical work queues remain open.

Approval queue hardening: excludes modules affected by read-only or unavailable service status. Regression fixtures exercise both specialist domains and verify that a laboratory-only approval grant cannot expose forensic work. Tests pending on the new head.

Digital forensic handover: a new explicit `forensics.reassign` grant allows a coordinator to transfer an open analysis to an eligible worker in the same active unit. The transaction preserves report and lifecycle state, updates assignment and audit/activity, emits a new assignment notification and reindexes. Stale edits are rejected. New worker/coordinator/requester templates are additive; existing custom roles are never silently modified. Cross-unit transfer and browser acceptance remain pending.

Handover UI: coordinator-only inline action on the analysis detail, named eligible examiners, required reason, explicit confirmation and error handling. Unsaved report fields block handover. Status and report saves advance the optimistic timestamp monotonically. Actual browser acceptance pending.

Legal correspondence: My Work now includes incoming open requests addressed to a responder's active team and the author's outgoing requests (including final replies). Each entry requires the same event-level legal request read grant and canonical court matter authorization, and links to the existing requests tab. The event-level legal inbox now respects court outages. Legal unit-wide and event-wide queue views, controlled report disclosure and browser acceptance remain pending. Fixed additive-role bootstrap regression expectations with explicit checks of the new coordinator grants.

Legal report delivery guard: linked records must match specific request types, specialist reports must already be approved, and the original requester must have canonical access before delivery. No implicit disclosure grants. Current and historical linked identifiers are redacted when visibility is revoked; free-text correspondence remains part of the legal matter. Cross-event, wrong-type, unapproved and inaccessible report regressions added. CI pending.
