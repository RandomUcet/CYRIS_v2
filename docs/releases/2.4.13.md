# CYRIS v2.4.13 — Administrator account lifecycle and ubiquitous EXCON composer

This PR is intentionally stacked on v2.4.12 (PR #38); it cannot be released until v2.4.12 passes its CI/release gates.

## LDAP account lifecycle: real backend operation
- Platform-admin-only `PATCH /api/admin/settings/identity/ldap/accounts/:identityId/status` accepts a strict boolean `enabled` and an audit reason (8–500 characters).
- Supports disabling and re-enabling LDAP-only CYRIS users. Disabled accounts remain searchable in the management UI and appear in a server-side status filter.
- A disabled user is denied on each session validation; disabling also attempts immediate Redis session revocation. The database status remains the authoritative denial even when Redis cleanup is unavailable.
- Audit event includes actor, identity and reason. Repeating an already-complete state transition does not create duplicate audit entries.
- Self-lockout, accounts with platform administration, mixed authentication identities and ambiguous multi-identity users are protected. Platform admins must remove platform management access before disabling that account.
- This controls **CYRIS account status**, not the LDAP/AD entry in the external directory. It is distinct from pausing membership in one exercise.
- Existing per-event LDAP team assignment remains available only for an active account in an open exercise.

## User and identity administration UI
- Three distinct access management sections: **Exercise participants**, **LDAP accounts**, **Platform administrators & preview**.
- Exercise participants can be explicitly paused/reactivated from the roster without disabling their global CYRIS login; this uses existing audited membership APIs and named confirmation.
- New responsive searchable LDAP account workbench with active/disabled server filters, account status badges, team/role editor and prominent account lifecycle controls.
- Confirmation of account status changes requires an explicit reason and entering the user's email address.
- Platform administrator management no longer hides in an additional collapsible form.
- Account search applies the proper event boundaries for membership data. Search results show at most 50 directory identities and clearly disclose the limit.

## LDAP/OIDC provider configuration improvements
- Identity provider settings now link directly to the separate LDAP account and role management workspace.
- LDAP group mapping cards now expose an explicit exercise-wide role option, rather than forcing a specific team for every new mapping; the UI clarifies whether a rule targets the whole exercise or one team.
- OIDC providers can be opened for **editing** rather than recreated. The existing provider UUID, unedited scopes, allowed email domains, and claim mappings are retained. Leaving Client Secret blank preserves its stored encrypted value.
- OIDC fields now have associated accessible labels, valid URL input and neutral empty defaults rather than example credentials that might accidentally be saved.
- OIDC modal separates a scrollable form body from the header and Save/Cancel footer on smaller displays. LDAP provider edits also surface network failures inline without discarding the form.
- Provider enable/disable and deletion operations have a clear busy state and are protected against overlapping requests; disabling and deleting require a confirmation naming the affected provider and describing the impact.
- Connection/configuration checks remain explicitly configuration-only; they do not claim to validate live network connectivity.

## Global quick EXCON broadcast
- Authorized organizer action in the top bar on every authenticated CYRIS page, including Administration. When no event is selected, the operator must explicitly pick one.
- Accessible responsive drawer: event and target audience, audience preview, four notice types, title and message, save draft, optional AI-assisted rewrite and **human review before send**.
- Server authorization, active-event check, mandatory urgent notice policy, recipient preference handling, audit and transactional idempotency remain authoritative and are reused unchanged.
- Failed sends may be retried with the same idempotency key; changing message content, scope or type creates a new key. Drafts use a separate key.
- The advanced broadcast workspace remains accessible for scheduling, history and delivery/read receipts.

## Verification & rollout
- Added isolated PostgreSQL tests for disable/reenable, self-lockout, multi-login/admin protections, audit and disabled-account search.
- Added pure frontend account policy tests and source-level quick drawer / permissions / confirmation regression checks.
- No new database migrations, no new external communications channels or autonomous AI sends.
- Browser accessibility and responsive acceptance remain required; **GitHub Actions CI runner allocation is blocked** as tracked in issue #39.
- Do not merge or publish this release until exact-head branch CI and the upstream v2.4.12 gate both pass, including production build, typecheck, regressions and encrypted backup restore.
