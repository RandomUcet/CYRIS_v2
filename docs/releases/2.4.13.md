# CYRIS v2.4.13 — Administrator account lifecycle and ubiquitous EXCON composer

This PR is intentionally stacked on v2.4.12 (PR #38); it cannot be released until v2.4.12 passes its CI/release gates.

## LDAP account lifecycle: real backend operation
- Platform-admin-only `PATCH /api/admin/settings/identity/ldap/accounts/:identityId/status` accepts a strict boolean `enabled` and an audit reason (8–500 characters).
- Supports disabling and re-enabling LDAP-only CYRIS users. Disabled accounts remain searchable in the management UI and appear in a server-side status filter.
- A disabled user is denied on each session validation; disabling also attempts immediate Redis session revocation. The database status remains the authoritative denial even when Redis cleanup is unavailable.
- Audit event includes actor, identity and reason. Repeating an already-complete state transition does not create duplicate audit entries.
- Self-lockout, accounts with platform administration, mixed authentication identities and ambiguous multi-identity users are protected. Platform admins must remove platform management access before disabling that account.
- This controls **CYRIS account status**, not the LDAP/AD entry in the external directory. It is distinct from pausing membership in one exercise.
- Existing per-event LDAP team assignment remains available only for an active account in an open exercise.

## User and identity administration UI
- Three distinct access management sections: **Exercise participants**, **LDAP accounts**, **Platform administrators & preview**.
- Exercise participants can be explicitly paused/reactivated from the roster without disabling their global CYRIS login; this uses existing audited membership APIs and named confirmation.
- New responsive searchable LDAP account workbench with active/disabled server filters, account status badges, team/role editor and prominent account lifecycle controls.
- Confirmation of account status changes requires an explicit reason and entering the user's email address.
- Platform administrator management no longer hides in an additional collapsible form.
- Account search applies the proper event boundaries for membership data. Search results are paginated, with up to 50 directory identities per page.

## LDAP/OIDC provider configuration improvements
- Identity provider settings now link directly to the separate LDAP account and role management workspace.
- LDAP group mapping cards now expose an explicit exercise-wide role option, rather than forcing a specific team for every new mapping; the UI clarifies whether a rule targets the whole exercise or one team.
- OIDC providers can be opened for **editing** rather than recreated. The existing provider UUID, unedited scopes, allowed email domains, and claim mappings are retained. Leaving Client Secret blank preserves its stored encrypted value.
- OIDC fields now have associated accessible labels, valid URL input and neutral empty defaults rather than example credentials that might accidentally be saved.
- OIDC modal separates a scrollable form body from the header and Save/Cancel footer on smaller displays. LDAP provider edits also surface network failures inline without discarding the form.
- Provider enable/disable and deletion operations have a clear busy state and are protected against overlapping requests; disabling and deleting require a confirmation naming the affected provider and describing the impact.
- Connection/configuration checks remain explicitly configuration-only; they do not claim to validate live network connectivity.

## Global quick EXCON broadcast
- Authorized organizer action in the top bar on every authenticated CYRIS page, including Administration. When no event is selected, the operator must explicitly pick one.
- Accessible responsive drawer: event and target audience, audience preview, four notice types, title and message, save draft, optional AI-assisted rewrite and **human review before send**.
- Server authorization, active-event check, mandatory urgent notice policy, recipient preference handling, audit and transactional idempotency remain authoritative and are reused unchanged.
- Failed sends may be retried with the same idempotency key; changing message content, scope or type creates a new key. Drafts use a separate key.
- The advanced broadcast workspace remains accessible for scheduling, history and delivery/read receipts.

## Further UX hardening in the same 2.4.13 draft
- Platform LDAP account list no longer requires any exercise selection: global account search, active/disabled filters, and lifecycle actions remain available in the admin area. Selecting an exercise adds only scoped membership, team and role tools. An operator can explicitly return to the global account list.
- Server-side directory pagination (50 per page) replaces the former hard 50-account ceiling. Pagination is bounded and uses deterministic name/email/identity ordering, with page reset when searching or filtering.
- The ubiquitous EXCON quick composer renders via a document-body portal, avoiding sticky header stacking contexts that hid or clipped its modal in some admin and workspace layouts.
- Four bilingual operational templates cover briefings, SITREP requests, situation updates and urgent instructions. Applying a template warns before overwriting an unsaved message.
- Templates with unfilled `[DOPLŇTE]` / `[FILL IN]` fields cannot be sent as live messages; unfinished templates can still be saved as drafts. Existing human review, server authorization, recipient preview and delivery idempotency remain mandatory.
- Added test coverage for global LDAP account lookup, paging limits and UI controls, portal layering and template placeholder validation.

## Follow-up fixes: account diagnostics, audit and safe delivery
- Directory account detail now exposes the last successful **CYRIS user login** timestamp and whether the linked LDAP identity provider is enabled. Provider-level disablement is shown as distinct from user account deactivation, with a warning that reactivating the user alone cannot restore a disabled provider.
- LDAP provider configuration uses a modal with a **scrollable body and persistent Save/Cancel footer**, including at narrow viewports and with long group-mapping lists.
- Required LDAP directory attribute fields are permanently visible instead of hidden behind a collapsible details section, avoiding native invalid-control focus failures.
- Platform-admin listing and updates now handle network exceptions with visible errors and retry instead of an indefinite spinner/unhandled rejection. Participant lists likewise recover from network errors.
- Command-role assignment/revocation and participant-membership reactivation require a deliberate user confirmation. Existing server permissions remain authoritative.
- EXCON quick-send refreshes the eligible-recipient count directly before final delivery. If the audience count changed since review, the operator must review and confirm again; this is a UX preflight, not a transactional guarantee that a roster cannot change before server commit.
- LDAP identity details link to a **server-filtered audit history** by user ID. The audit screen now supports backend paging rather than only the first 100 records, preserving the admin authorization checks.
- Added regression source checks for modal layout, error recovery, linked account audits, paginated audit requests, LDAP provider metadata and the final broadcast preflight. CI / browser acceptance is still pending.

## Additional administration reliability fixes
- Fixed a TypeScript compile blocker in LDAP account paging (the page-number argument and a local page-slice variable previously shared the same identifier).
- LDAP identities remain visible and can be audited/deactivated **even after their original LDAP integration is deleted**. Provider removal is shown distinctly; team/role edits are disabled until a valid provider is restored. The external directory is not modified.
- Account deactivation success text accurately describes the authoritative database-backed denial of sessions, without assuming Redis cleanup succeeded.
- Security audit category options now use actual persisted category values rather than invented uppercase choices that produced empty result lists.
- Clearing a deep-linked user filter resets the audit page state as well as its URL, even when Next.js reuses the same page component.
- Audit free-text searches now filter **the whole authorized history on the server before paging**. They are bounded to 160 characters, use literal case-insensitive substring matching, and are debounced by the UI; matching counts come from the backend.
- Added isolated-PostgreSQL assertions for orphaned LDAP identity lifecycle and audited search, plus frontend source-regression checks.

## Administration continuity and account safety follow-up
- LDAP accounts whose original login provider was **deleted** remain listed in the administration workbench. They can still be suspended with audit and server-side session denial; the UI identifies missing providers and blocks team reassignment until the identity provider is restored.
- Fixed a duplicate local `page` variable in the LDAP query service that would otherwise prevent TypeScript compilation.
- Security audit category selectors now match real stored values (`identity`, `authorization`, `integrations`, `membership`, `scenario`, `medical`, `support`) instead of uppercase placeholders that could never match.
- Audit search now runs against **all permitted rows on the database**, with a bounded, parameterized literal substring query; client input is debounced, counts reflect the server result and stale requests are discarded. A pending search hides old results, and changing category closes the previous event inspector. Audit filtering by account ID and pagination still apply. Page and limit parameters reject fractional values.
- Clearing the account-audit deep link now clears component state immediately, rather than relying on a same-page navigation to force a remount.
- The identity settings link opens the **LDAP tab** directly (`/admin/users?tab=ldap`). Admin user-management tabs now preserve navigation state in the URL and reset to ordinary participants if platform-admin rights disappear.
- Tests expanded for deleted LDAP providers, persisted audit search and wildcard literals, query limits, audit category values and deep links. These are committed but await a working CI runner.

- Added pure frontend account policy tests and source-level quick drawer / permissions / confirmation regression checks.

## Runner recovery and release artefact safety (2026-11-23)
- **Release pipeline remains blocked** until the GitHub runner is assigned and all checks run on the exact commit. Jobs with 0 steps and no runner are infrastructure failures, not proof of application correctness.
- Workflow runner selection can use protected repository variables `CYRIS_CI_RUNNER` and `CYRIS_RELEASE_RUNNER` to choose distinct isolated Linux VMs while preserving the full CI and encrypted backup-restore gate. GitHub-hosted `ubuntu-latest` remains the default.
- A read-only `node scripts/release-doctor.mjs --run <run-id>` identifies unavailable runners, executed-step failures, green jobs and missing official release assets.
- Release workflow now verifies that all three published GHCR digests exist and contain **linux/amd64 and linux/arm64** before writing a release manifest or creating a GitHub Release.
- Operator instructions: [release runner recovery](../v2/release-runner-recovery.md). CI outage issue: [#39](https://github.com/RandomUcet/CYRIS_v2/issues/39).
- Do not merge/publish for the sake of a version number. No production server changes until build, typecheck, DB regressions, isolated restore and official release assets are confirmed.
