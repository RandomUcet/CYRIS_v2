# CYRIS v2.1.1 — urgent backup/restart hotfix

The v2.1.0 updater failed during its pre-migration encrypted backup. It used
`docker compose start --wait --wait-timeout 240`, but the `start` subcommand
does not support `--wait`. The updater aborted before it encrypted and verified
the snapshot or ran database migrations, and resumed the old application in error
recovery. The user-provided `doctor --full` showed READY, but did not prove 2.1.0
had been installed.

The fix changes service restoration to
`docker compose up -d --no-deps --no-recreate --wait --wait-timeout 240` for
exactly the services running before the backup. Tests check the command and the
restart path after a snapshot write error. No new application feature or schema
change relative to v2.1.0; all package identities and release manifests use 2.1.1.

## Update an affected Ubuntu server

Run over SSH:

```bash
sudo cyrisctl self-update
sudo cyrisctl github verify
sudo cyrisctl update --version v2.1.1
sudo cyrisctl status
sudo cyrisctl doctor --full
```

Success requires the updater to print `Running verified CYRIS release 2.1.1.`
and status to show `Version 2.1.1`.

The update stops services while creating and verifying a full encrypted
pre-migration snapshot. Keep the recovery key and archive safe. If any step
fails, preserve logs; don't delete volumes or manually force migrations.

This hotfix is published via the standard GitHub Release workflow. Updating
the actual VM remains a separate explicit `cyrisctl update` operation.
