# CYRIS v2.2.0 — REFOUNDATION workflows and safety

**Candidate under review.** This document describes changes in the source tree. It is not a certification of 100% security or perfect browser behavior.

## Shipped code
- Responsive modal styling and accessibility for Medical, Court/Legal, Forensics, Lab, Evaluation, Cases, Evidence, Registry, Incidents, Tasks, Command and administration.
- Court record selectors (search people, related cases, evidence, documents rather than copy UUIDs).
- Spark scenario mode prominently displayed, with validated private image uploads to *unpublished drafts*, previews, removal, and transactional attribution to generated Registry records when published (5 MiB/image; at most 50 images/batch; files not sent to AI).
- New Scenario Preflight: structural checks for requested counts, duplicate full names, valid references, weak descriptions and image coverage, with advisory score.
- Relations graph: searchable record titles/identifiers, combined type filter, connected-record count.
- Support: paginated subject/category filtering, automatic eligible support responder assignment and audited manager reassignment with optimistic concurrency.
- Administrator operational holds with event/team/person/module targeting, reason, expiration, restoration and participant notice, distinct from simulated outages.
- Secure escaped global search highlights and real internal navigation; login IP source validation and fail-closed login rate limiter.

## Important remaining limitations
- **Not a complete whole-exercise freeze**: some background, non-event and in-flight writes are not yet covered. Do not rely on this mechanism for emergency system shutdown.
- No web-triggered privileged encrypted backups yet; the safe supported way is host-side cyrisctl backup. Do not expose a root shell or Docker socket to web admins.
- Exact-device/browser/role acceptance, Spark hardware E2E and a full security penetration test are not replaced by CI and remain outstanding.
- CSP/proxy and other security follow-ups remain in issue #19; residual backlog is issue #18.
- Automatic support assignment requires eligible active event managers; tickets remain in the support queue when none exists.

## Release acceptance
Require exact-head successful build, typecheck, PostgreSQL migration, automated regression tests, deployment-script validation and isolated encrypted backup recovery.
Before a production upgrade, verify multiple real user roles on a disposable/staging exercise and retain a tested encrypted backup and rollback plan.
**Never update a production server until the final official GitHub Release exists.**
