# CYRIS v2.4.3 — Medical exercise isolation

## Fix
- New medical encounters validate each linked scenario person, incident and location against the requested exercise and expected registry type.
- Medical updates validate linked person, location, assigned team and assigned operator against the encounter's actual exercise before changing any record.
- Medical handoffs validate the target location and receiving team against the encounter's exercise **before** recording a transfer.
- Assigned operators must be active members of the same exercise. Newly assigned teams must be active (not archived) units in that exercise. Optional link clearing with `null` remains supported.
- Foreign UUIDs no longer lead to cross-exercise medical relationships, patient/team misassignment or handoffs. Invalid input yields an explicit client error without querying data from the other exercise.

## Regression
- Disposable-PostgreSQL tests create two independent exercises and verify matching and mismatched scenario identities, record types, units, inactive memberships, archived units, invalid new encounter creation, updates and transfers.
- Failed update and transfer assertions verify the existing encounter remains unchanged.
- Existing read / write resource authorization from v2.4.2 remains in force.

## Operations
- No new database migrations, destructive data operations, new secrets or external integration configuration.
- This fix protects operations via the medical module API; an exhaustive system-wide cross-domain reference audit remains separate work.
- Exact-head CI, backup/restore and matching image digests must pass for this candidate. Browser acceptance with multiple team profiles and real role assignments remains necessary before production use.
- Publication creates a versioned GitHub release only, not a production server update.

## Upgrade Ubuntu after publication
```bash
sudo cyrisctl self-update
sudo cyrisctl github verify
sudo cyrisctl update --version v2.4.3
sudo cyrisctl status
sudo cyrisctl doctor --full
```
