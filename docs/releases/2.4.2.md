# CYRIS v2.4.2 — Medical authorization boundaries and printable triage run sheet

## Security / correctness
- Medical encounter creation now checks the authenticated operator's `medical.create` capability in the requested exercise before allocating identifiers or creating records. Event-wide and eligible team capabilities work; unrelated logged-in users are rejected.
- Medical operational summary requires appropriate `command.read` or `medical.read` event capability (or platform administration). Previously, the standalone endpoint only verified authentication.
- Every encounter-specific HTTP route (read, update, triage, observations, interventions, stabilize, transfer and close) now verifies that the record belongs to the event in the URL before delegating to domain operations.
- Regression tests cover unauthorized creation/summary, mismatched URL exercise across all eight routes, and workspace/print filter parity. The existing per-resource medical authorization remains mandatory.

## New operator capability
- **Medical run-sheet print/PDF** from the medical workspace. Open the dedicated authenticated print view in a new tab; browser print can save PDF.
- The printable sheet preserves the current active/triage/transfers/all view, triage filter, and text search. It includes identifier, person, triage, status, complaint, team and opening time.
- Print retrieves only records from the existing authorization-filtered `GET /events/:eventId/medical` endpoint. It cannot print or enumerate other units' patient details.

## Scope and release acceptance
- No new database migrations; no broad data deletion or access model changes. Partial/full cleanup remains disabled pending issue #21.
- This is a source-level/automated regression release, **not** proof of clinical workflow browser acceptance. Verify medical creation, per-team privacy, scenario event separation and A4 pagination with realistic exercise data before production deployment.
- GH Actions must pass on the exact candidate commit and publish immutable digest-pinned images and matching Ubuntu bundle.
- Production server is not automatically changed by a published GitHub release.
