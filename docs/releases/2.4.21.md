# CYRIS v2.4.21 — platform optimization, first pass

- Scoped CSS repairs for EXCON/broadcast including responsive grids, typography, theme contrast, focus, forms and reduced motion. Static regression coverage is not browser visual validation.
- Shared service-status provider now uses the same in-flight guard for manual and automatic refresh; hidden tabs skip periodic calls and refresh when visible. Scope includes event, user and view-as identity.
- DEFCON polling retains its five-second interval and catches network errors; unchanged snapshots retain their reference, avoiding unnecessary updates. No change to alert delivery semantics.
- All three Dockerfiles fetch locked dependencies before versioned manifests; frozen installs and dual-architecture digest verification remain. Actual cold/warm build durations must be verified.
- No migrations, removed modules or production deployment.

## Second pass — authorization and Spark history
- Batch event capability lookup uses four SQL queries for a nonempty active membership (one membership, then unit/platform/event grants), instead of repeating these per permission. No persistent authorization cache. Existing single-check callers share the same policy; real PostgreSQL regressions cover active/disabled/cross-event identities and unit binding.
- Service-status filters all affected modules using one batch capability resolution. Empty requests do not query the database. Actual latency remains to be measured.
- Spark history computes draft link count in PostgreSQL without loading full generated records; independent metadata/name lookups run concurrently and redundant non-person world generation/blueprint validation are removed. No provider speedup claimed.
