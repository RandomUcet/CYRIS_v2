# CYRIS v2.4.21 — cumulative platform update

- Scoped CSS repairs for EXCON/broadcast including responsive grids, typography, theme contrast, focus, forms and reduced motion. Static regression coverage is not browser visual validation.
- Shared service-status provider now uses the same in-flight guard for manual and automatic refresh; hidden tabs skip periodic calls and refresh when visible. Scope includes event, user and view-as identity.
- DEFCON polling retains its five-second interval and catches network errors; unchanged snapshots retain their reference, avoiding unnecessary updates. No change to alert delivery semantics.
- All three Dockerfiles fetch locked dependencies before versioned manifests; frozen installs and dual-architecture digest verification remain. Actual cold/warm build durations must be verified.
- No migrations, removed modules or production deployment.

## Second pass — authorization and Spark history
- Batch event capability lookup uses four SQL queries for a nonempty active membership (one membership, then unit/platform/event grants), instead of repeating these per permission. No persistent authorization cache. Existing single-check callers share the same policy; real PostgreSQL regressions cover active/disabled/cross-event identities and unit binding.
- Service-status filters all affected modules using one batch capability resolution. Empty requests do not query the database. Actual latency remains to be measured.
- Spark history computes draft link count in PostgreSQL without loading full generated records; independent metadata/name lookups run concurrently and redundant non-person world generation/blueprint validation are removed. No provider speedup claimed.

## Third pass — notification center
- Read visibility evaluates module impacts once per event and platform override at most once per request, rather than per module. No cross-request authorization cache.
- Bulk acknowledge selects distinct event/template groups, marks only visible unread groups with event/user and creation-time boundary. Hidden receipts remain unread after recovery. Individual dismiss now follows the same visibility rule as read.
- Browser refresh is single-flight within scope, post-mutation reload waits for older request and then refreshes; mutation lock is synchronous and stale actions cannot update the new scope.
- PostgreSQL integration exercises hidden receipts, global/event scope, idempotent bulk read and restoration. Existing 100-row list limit remains; no production performance benchmark yet.

## AI transport resource lifecycle
- Normal TLS uses the existing shared global fetch dispatcher. Explicit insecure-TLS overrides now allocate only when a request runs and destroy the private agent in all exit paths (including failure). No changes to TLS defaults or provider credentials.
- Connection probes cancel unread HTTP bodies before retry/return, including embedding errors. Mock transport tests assert cleanup and standard TLS behavior. No actual DGX speed or memory measurement yet.

## Search optimization pass
- Batch role and unbound unit grants across active memberships, retaining membership/event matching and bound-unit isolation. Module outage checks remain per event. Reject nonliteral caller-supplied filter fragments for every identity, including administrators.
- Typesense returns only fields needed by the response mapping (highlights remain available); upstream failures return explicit 503 rather than false empty results.
- Command palette aborts outdated browser requests, remounts on identity/event/preview scope changes, hides stale results, and follows grouped visual keyboard order. Admin audit shortcut hidden from non-platform users. No caching of authorization.
- Existing database indexes reviewed; no speculative migration without EXPLAIN/production data. Regression tests cover malicious filter fragments and unit scope. Browser and Typesense live timing not measured.

- Shared resource picker and legacy global search dialog now cancel requests and clear stale results on query changes or scope switches. Person picker retains canonical registry API and cancels its requests without retrying aborts. Selected records that cannot be resolved can be cleared explicitly. Static picker regressions updated; browser acceptance pending.

## Administration performance
- Membership response assembly groups role/unit data by IDs once rather than scanning all assignments for every member; identical API contract and permission checks. This changes in-memory complexity, not the SQL index schema.
- Participants and roles are loaded only on the participant tab; outdated requests are aborted on scope/tab switch. Shared DataTable gains opt-in pagination (50 rows in roster), whole-result sorting and filter/scope reset. Empty roster queries skip text normalization. Browser and real event load timing pending.

## Screenshot-driven UI corrections
- Document drawer, list, preview and upload forms use consistent semantic surfaces/text rather than mixed hardcoded dark colors. Wider preview, readable extracted text and version upload errors. Scope remount and event-specific write checks.
- Stronger scoped EXCON contrast/metric layout and progress bars, composer fieldset layout, legal inbox top alignment, localized states and configured date/time. Browser visual verification still required.

- JSOC now explains roles and workflow, distinguishes label from AI prompt, supports optional category-specific deterministic generation and dataset-label search. Existing mixed payloads compatible; no live CYLAB or network integration, no automatic incident/notification. Focused fixture test added. Module availability distinguishes real write lock from simulated module outage visually and in copy.
