# CYRIS v2.4.1 — Briefings repair and participant print

## Fixes
- Platform administrators no longer receive a membership-based 403 from the Briefings service after the permissions guard has authorized them. The platform permission is verified server-side by the existing authorization service; regular participants still need active event membership and the appropriate audience.
- Workspace briefing badge reads individual `scenario_briefing_receipts`, not the obsolete shared delivery read state. It counts distinct released briefings rather than duplicate language/recipient deliveries and applies the same direct-recipient/assigned-unit restrictions as the inbox.
- Briefing read/acknowledge errors are visible alongside previously loaded messages, with an explicit retry action.
- Regression verifies platform-administrator access without event membership, recipient isolation and independent per-user receipts.

## New capability
- Authenticated printable participant briefing inbox, available through the **Print / PDF** action. The existing A4 PrintSheet supports browser printing and Save as PDF, with read/ack states and authorized disclosed resources.
- Print uses the normal participant endpoint and omits controller summaries, secrets and unreleased injects.

## Operations and limitations
- No database migration and no destructive operations added. Actual event purge remains disabled, see issue #21.
- **No automatic production deployment.** Validate role/audience behavior and print output in a disposable exercise before upgrading a live event.
- The reported Briefings error has a confirmed contradictory admin authorization path fixed here. Other causes of a production error would require server logs; this release does not claim to fix unknown failures.
- Backups, encrypted recovery, exact-head CI, digest-pinned images and release workflow must complete before publication.

## Update Ubuntu after official release
```bash
sudo cyrisctl self-update
```
