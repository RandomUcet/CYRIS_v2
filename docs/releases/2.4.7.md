# CYRIS v2.4.7 — Reliable continuous integration

## CI execution and release gates
- Pull requests run CI **once per PR revision** via `pull_request`. Branch push runs no longer duplicate the same checks before or alongside the PR workflow.
- Every push to `main` continues to trigger standalone CI. The `Release` workflow continues to invoke the full reusable CI gate using `workflow_call`. Manual `workflow_dispatch` remains available.
- Superseded runs are cancelled **only** when a newer commit arrives on the same PR. The concurrency group includes the workflow identity and uses a unique run ID for non-PR events; main CI and release validation are not accidentally cancelled or coalesced.
- The CI validation job has a 25-minute upper bound. This does **not** limit the separate multi-architecture Docker publishing step in the Release workflow.

## Reliable test failures
- The sequential `node:test` runner receives a 10-minute watchdog. A hung nested test or unresolved async operation now returns exit code 124 with a useful error instead of occupying a runner indefinitely.
- Standard test failures still keep their original nonzero exit code and report elapsed runtime. Existing test discovery, sequential isolated PostgreSQL fixtures, backup restore checks and deployment-script checks remain intact.
- Added regression checks for PR/main/reusable workflow triggers, cancellation scope, release gate integrity and bounded test execution.

## Scope / operator verification
- No application domain changes, database schema migrations, role changes, deployment config modifications or destructive actions. This release hardens the **build and release pipeline**, not runtime modules.
- As with all CYRIS releases, successful GitHub Actions publication does not automatically update a deployed server.

## Ubuntu update (after the official GitHub Release appears)
```bash
sudo cyrisctl self-update
sudo cyrisctl github verify
sudo cyrisctl update --version v2.4.7
sudo cyrisctl status
sudo cyrisctl doctor --full
```
