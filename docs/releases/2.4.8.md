# CYRIS v2.4.8 — Trusted request ID and audit provenance

## Security: no untrusted audit identity from raw headers
- Fastify now sets `requestIdHeader: false` so it **always** calls the existing request ID validator. Previously configuring `requestIdHeader: 'x-request-id'` caused Fastify to accept that raw header verbatim and skip `genReqId` entirely.
- Caller-provided correlation IDs are allowed only if they match `[A-Za-z0-9_-]{8,64}` (surrounding whitespace trimmed). Otherwise the server issues a new UUID. The validated value is used for `req.id`, `X-Request-ID` response headers and the audit trail.
- Auth login/logout audit and the denied-permission guard use **`req.id`** rather than re-reading the original untrusted `X-Request-ID`.
- Permission-denial audit uses `req.ip` rather than trusting the raw client-controlled `X-Forwarded-For` header. This matches login/logout IP identity and stops audit source spoofing through arbitrary headers.
- Event administration audit controllers for events, teams, roles and memberships now also use the validated `req.id` instead of raw `X-Request-ID`, avoiding inconsistent attribution across privileged operations.

## Tests
- A real Fastify injection regression verifies valid correlation IDs survive unchanged, malicious IDs are replaced with safe UUIDs and the response header reflects the validated request.
- Unit regression checks oversized/control-character/non-string IDs and the permission-denial audit under forged forwarding/request ID headers.
- Release gate remains full exact-head CI, disposable PostgreSQL regression and encrypted backup restore.

## Proxy limitation and scope
- **No broad proxy trust enabled.** `req.ip` is the connecting peer (possibly Next/Caddy), not necessarily the original browser IP. This avoids spoofing but may group clients behind one proxy in login rate limiting; the real deployment path and narrow trusted-proxy setup still require separate verified ingress testing.
- No schema changes, destructive action, new external configuration requirement or user-facing workflow changes.
- This is a targeted audit/trace integrity repair, not a completed CSP, CSRF or full ingress review.
