# JSOC simulated telemetry — operational boundary

This module is a **tabletop exercise simulator**, not a log shipper, SIEM,
monitoring connector, incident detector or source of live health information.

## Data and storage

- SQL migration `0024_jsoc_synthetic_logs.sql` adds event-scoped
  `jsoc_synthetic_logs` rows, deleted with their exercise.
- Every event is generated by EXCON with a chosen seed, count (10–100)
  and scenario description. Each record is explicitly prefixed
  *Simulated*, uses made-up training hostnames and RFC 5737 reserved
  documentation IPv4 ranges. No telemetry is ingested from real servers.
- A maximum of 5,000 rows per exercise is enforced transactionally with
  an event-scoped advisory lock. Generated datasets and actor identity
  are recorded in the audit trail.
- The user-facing source IP values are not observations of the CYRIS
  installation. Infrastructure health is instead in **Administration →
  System health**. Simulated restrictions are under **Service status**.

## Access model

- **EXCON**: an effective event `scenario.manage` permission permits
  generation and reading this synthetic event stream.
- **JSOC student**: an active membership in an unarchived unit with the
  `technical_operations` capability **AND** an effective
  event-scoped `forensics.read` permission is required to view logs.
- **Crisis command**: neither `crisis_management` capability nor
  `command.read` grants access to this endpoint.
- `View As`: only the exact GET log route is allowlisted; normal
  effective-principal permission and event membership checks still apply.
  POST generation is blocked.
- This is a *server-side* boundary. Hidden navigation alone does
  not authorize a user. A valid event UUID cannot bypass the checks.

## Operator workflow

1. Define a technical operations unit in the exercise and explicitly
   grant its JSOC members `forensics.read`.
2. EXCON opens **JSOC → Simulated logs**, enters a fictional scenario
   description, count and seed and confirms generation.
3. JSOC members open the page, filter severity/category/source, and
   inspect event details. Server returns data only for the current exercise.
4. Real infrastructure monitoring and actual incident response stay
   outside this simulation.

## Acceptance checklist

- Before applying a new version, back up the isolated Preview DB.
- Run all migrations on a disposable test database first.
- EXCON can generate; JSOC with both conditions can read, but not
  generate; crisis without JSOC rights receives HTTP 403 even using
  the direct API URL or another exercise UUID.
- Check with a populated exercise, real browser layout and CS/EN switch.
- Verify audit action `jsoc.synthetic_logs.generated`.
- No production rollout or schema migration occurs through this PR alone.
