# CYRIS 2.5 — product quality and missing domain capabilities

## Design acceptance
Use existing CYRIS tokens, actual operational data, deliberate hierarchy. Avoid dashboard-by-template: gradients, repeated equal KPI cards, decorative status colors, redundant labels, all-caps and disclosure for small groups. Dense readable lists and tables for work; scenario clock and actionable exceptions first in EXCON. Presentation is a viewing surface, not a copy of administration. No fabricated metrics or public disclosure. Inspect desktop/mobile/light/dark and keyboard behavior before release; obtain user screenshots for visual acceptance.

## Local test accounts
Existing LocalIdentityProvider hashes with Argon2id; existing preview team switch governs generated preview accounts, not arbitrary local testers. Add admin-only individual provisioning in Users & Access, not reuse shared team passwords. Explicit event, unit and ordinary existing role selection; no platform privilege grants, no LDAP/OIDC auto-link by email, password only once (no audit/logs), revoke sessions on disabling, expiry and audit. Require testing of direct authorization, session revocation, identity collision, no unintended cross-event access, and coexistence with preview mode. No secret in GitHub.

## Scenario permits and licences
Create fictional registry records, not real permit issuance. Distinguish person/organisation holder, permit type, issuing authority, identifier, valid from/to, suspension/revocation and verification status from asset ownership. Link to canonical persons, organizations, weapons, vehicles and documents through existing resource visibility/relationship policies, with event-scoped integrity and audit. Never infer authorization from possession or a missing record; differentiate unknown/expired/revoked/valid-on-selected-date, avoid declaring real legal compliance. Support historical versions, registry search, detail backlinks, printable record and scenario generation with coherent fictional licences. Use verified Czech legal sources if implementing actual legal classification; do not encode speculative categories as law.

## Role-to-workspace quality gate (2.5)
Treat capability labels as relevance, not authority. A mixed-role member must receive the union of permitted modules, including scoped record lists; exact event-only endpoints must not be advertised based solely on a capability. Unit-bound roles must become inactive when membership or the unit ceases to be active, consistently in resource access, profile, search and navigation. Real test accounts use the selected active unit and validated event role. Verify grant/revoke while signed in, multiple teams, disabled/expired accounts, view-as, cross-exercise direct URLs and resource visibility.
Browser acceptance matrix: organizer, investigator, laboratory operator/lead, forensics/JSOC, medical, command, tactical, prosecutor, defence, judge, observer, read-only and no-grant members. For every role verify menu, landing page, list, detail, empty/loading/error state, record actions, direct URL, search and mutations with actual DB grants; compare desktop/mobile and light/dark. No visual acceptance claim until a browser and running isolated deployment are available. Add integration coverage for each identified mismatch rather than replacing existing checks.

## Scenario publication performance
Bounded 250-row inserts for resource identities, domain rows, staged media and typed search outbox events; one outbox upsert per canonical record after all relations are inserted in the same transaction. Bulk deletion retains per-record durable outbox semantics. This reduces publication SQL round trips but does not measure actual DGX Spark inference latency. Profile generation and publication separately on the running exercise environment.

The participant roster now has a general role-grant/revoke dialog (not only the hard-coded command shortcut), including optional team binding, exact existing assignment, permission scope preview, duplicate protection and refresh after changing one's own grant. The catalog is exercise-scoped; no platform role is assignable through this dialog.

Registry detail now resolves per-record edit/link/timeline affordances from the authoritative access service, fails closed when action metadata cannot load, fences outdated detail and activity responses, and distinguishes unavailable relationships from an empty graph. Licence validity can be checked against an explicitly selected date; automatic scenario-clock integration remains pending.

## Spark output reliability
Fast blueprint uses JSON object mode, 700 tokens and a 110-second inference limit (inside the 135-second web proxy budget); architect/advisor durable jobs use compact prompts, JSON object mode and 240 seconds. Reject truncated completions and invalid structure, never silently repair partial output or substitute local data. Stable diagnostic categories are visible in the job panel. Fast is now the API default for new drafts, existing saved detailed drafts retain their mode. Live managed Spark compatibility, throughput and inference response quality require hardware verification.

Scenario-data workspace can explicitly copy the current EXCON blueprint brief and objectives into its editable 1,200-character prompt; no live link or claim of automatic synchronization. Architect can submit a saved blueprint without requiring duplicate free-text input. Fast scene vocabulary now drives names and descriptions, with regression tests for asymmetric and person-only datasets. Relations remain deterministic by canonical indices, not inferred by the model.

Administration now separates model-discovery connectivity from a bounded real JSON inference probe against the saved managed Spark profile. No health status or enable switch is changed by the inference test. The diagnostic does not claim full exercise-generation performance.

Dataset background generation stores job state in the existing batch JSON, without a new table. Queued jobs persist across reloads; running pages can pause at a safe boundary. Capacity-only retry, explicit resume after interruption, no automatic publication. Legacy advance endpoint remains available for unqueued drafts. Hardware throughput and full multi-replica crash testing remain pending.
